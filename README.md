# synquery-agi-autonomous

Synquery AGI（社内 AGI）と Synquery web-platform 製品（当社主力製品と派生製品群）に関する情報発信のためのリポジトリです。

GitHub はデプロイ先ではありません。ここに置くのは、デプロイのためのツールや仕組み、手順書、毎日更新するネタです。

作業は二つの役割で分担します。戦略室が GTM 戦略を計画し、依頼書を発行します。Code が依頼書に沿って実装し、このリポジトリへの push と公開を行います。戦略室から Code へは依頼書（`requests/`）を ystskm が手で渡し、Code から戦略室へはこのリポジトリ（報告は `reports/`）だけで伝えます。このリポジトリに置かれていない成果は、戦略室からは存在しないものとして扱われます。Code の作業規則は `CLAUDE.md` にあります。

## 構成

| ディレクトリ | 中身 |
|---|---|
| `notes/` | 毎日のネタ。1日1ファイル、名前は `YYYY-MM-DD.md`（JST） |
| `guides/` | 手順書 |
| `tools/` | デプロイのためのツールや仕組み |
| `agi/` | Synquery AGI に関する資料 |
| `platform/` | Synquery web-platform 製品群に関する資料 |
| `requests/` | 戦略室からの依頼書。名前は依頼番号（`REQ-YYYYMMDD-NN.md`）。本文は書き換えない |
| `reports/` | Code から戦略室への報告。1回の実行ごとに1ファイル、名前は `YYYY-MM-DD-HHMM.md`（JST） |

## 公開の基準

このリポジトリは公開されています。`main` に入ったものは外に出たものとして扱います。

**置いてよいもの**
- 公開済み、または公開を決めた機能・仕組みの説明
- 一般化した手順や、汎用のツール
- 実測値。ただし出典と取得日を添える

**置かないもの**
- 顧客名、取引先名、個人名、連絡先（人物の指定表示は `ystskm` のみ許可）
- 内部の構成、ホスト名、認証情報、環境変数、API キー
- 未発表の機能、価格、提携
- 資金、評価額、資本政策、ランウェイ
- 法務・税務・知的財産の検討中の論点、契約の状況
- GTM の現在地スナップショットや未決事項（正の置き場は別にある）

迷ったものは置かない。

## 運用

- 作業はブランチで行い、プルリクエストを経て `main` に入れる。
- 事実・確定事項・仮説を混ぜない。仮説には〈仮説〉と付ける。
- 見出し・本文に絵文字や警告記号を使わない。

### 公開の手順

公開は Code の定期実行で行う。定期実行の時刻と頻度、`main` から先の公開先と形式は未決で、決まるまで次の暫定手順で運用する。

1. **何が、いつ `main` に入るか**
   - 依頼書に沿った変更を、Code（単発セッションまたは定期実行）がブランチに push し、プルリクエストを出す。
   - 当面は、`main` へのマージは ystskm が行う。定期実行は判定と報告までを行い、マージしない。
   - `main` に入った時点で公開されたものとして扱う。`main` から先の公開先への反映は、公開先が決まるまで行わない。
2. **公開の基準に照らした判定をいつ行うか**
   - Code は push の前に、追加・変更したファイルを「公開の基準」に照らして確認する。基準に当たるもの、または迷ったものは push しない。
   - 定期実行は、`main` に向いた未マージのプルリクエストを毎回もう一度判定し、結果を `reports/` に書く。基準に当たるものがあれば、そのプルリクエストに対応が要ることも書く。
   - ystskm はマージの前に、その判定結果を確認する。
3. **公開を止める方法**
   - 定期実行を止める：claude.ai の定期実行の設定で無効にする。無効にしている間は、push も判定も行われない。
   - マージ前の変更を取り下げる：そのプルリクエストを閉じる。
   - `main` に入った変更を取り下げる：該当する commit を打ち消す commit（`git revert`）をプルリクエストで `main` に入れる。履歴の書き換え（rebase・force push）はしない。
   - 取り下げたことと、その理由を `reports/` に書く。
